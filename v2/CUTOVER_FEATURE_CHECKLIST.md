## B. Идентичность данных при переходе (вакансии / кандидаты / статистика)



### B1. Что должно совпасть 1:1 после финального импорта


| Сущность          | Источник Streamlit       | Куда в v2              | Проверка                                        |
| ----------------- | ------------------------ | ---------------------- | ----------------------------------------------- |
| Клиенты/отделы    | `departments.json`       | `clients`              | count + имена                                   |
| Чаты              | `chats_db.json`          | `messaging_channels`   | count + chat_id                                 |
| Вакансии          | `vacancies_db.json`      | `vacancies`            | count active/archive, title, chat_id, documents |
| Кандидаты         | вложенные в вакансии     | `candidates`           | count, этапы, статусы, ссылки, payload          |
| History генераций | `data/history/*.json`    | `document_generations` | count ≈ файлов                                  |
| Шаблоны           | `vacancy_templates.json` | `vacancy_templates`    | count                                           |


**Статистика воронки** в v2 считается из тех же кандидатов/этапов после импорта — отдельный stats-файл не нужен, **если** кандидаты совпали.  
Периодная «продуктивность» / AI-baseline Streamlit **не** импортируются сами по себе (см. A6).

### B2. Обязательные доработки импорта (чтобы не было сюрпризов)

- [x] Snapshot `data/` → финальный `import_json --replace` без потери актуальности
- [x] Сверка счётчиков API (`/stats/import` + ручной просмотр 5–10 карточек)
- [x] Миграция `telegram_posts` → `messaging_posts` (старые карточки в чатах остаются кликабельными)
- [x] History: проставить `vacancy_id` / `client_id` при импорте (сейчас часто null)
- [x] Чистый `--replace`: wipe также messaging_actions/posts и hh_seen/shortlist (нет orphan-хвостов)
- [x] Документированный откат: снова Streamlit с того же snapshot



### B3. Что сознательно может не совпасть (если не отмечено в A)

- Google Calendar events / OAuth tokens  
- `zone_access` / client-zone токены в UI  
- `telegram_scheduler_state` (слоты дайджестов) — пока нет движка  
- HH shortlist/seen v2 (это runtime v2, в Streamlit JSON их нет)  
- Поведение reminder/attendance/warranty — данные в payload могут быть, логика заработает только после переноса фич
